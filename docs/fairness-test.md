# 형평성 제약 측정 (멘토 QA-10)

> `engine/assigner.py` 에 `fair=False` 옵션 파라미터 추가. `True` 시 "요청한 농가는 최소 1명 배정" 제약을 CP-SAT 모델에 더한다 (가용 인원 < 요청 농가 수인 날은 적용 불가 — `fairness_applied=False` 로 응답에 표기).
> **기본값 불변**: 11일(10/13~23) 전 날짜에서 수정 전 `assign()` 결과와 `fair=False` 결과가 **완전 동일**, `compare_baseline.py` 결과는 **소수점까지 동일**, 10/14 20회 반복 unique=1 유지.

## 측정 지표
- **off_zero / on_zero**: 요청 농가 중 0명 받는 농가 수
- **off_min / on_min**: 농가별 충족률(배정/요청)의 최솟값
- **off_total / on_total**: 배정 점수 합계 (fair 제약 **비용** = `on_total − off_total`)
- **same**: fair 켜고 끈 배정 결과가 완전히 동일한지
- **고령 농가**: F01 (고령 농가 A, 70대)·F05 (고령 농가 E, 80대) 를 요청한 날에 각각 몇 명 받았는지

## 4. 형평성 제약의 "비용"

모든 측정 날짜에서 **총점 변화 Δ = 0**. 11×3 = 33 개 측정 포인트 중 **단 하나(스트레스 15명 10/14)**에서만 fair 가 배정 구성을 바꿨고, 그 경우에도 총점 손실은 없었다 — CP-SAT 가 동점 최적해 중에서 더 균등한 쪽을 선택할 수 있었기 때문. 이 데이터셋에서는 **형평성 제약의 비용 = 0**.

> 주의: 총점 손실이 0인 것은 측정값일 뿐 **일반 결론이 아니다**. 요청 분포가 더 치우쳐 있거나 농가 수가 더 많으면 fair 가 총점을 희생할 수 있다. 운영 데이터로 재측정 필요.

## 5. 노출 범위 결정

- **실 데이터(20명) 에서 fair=True 가 결과를 바꾸는 날이 0/11** 이라, 현장 UI 에 토글을 노출해도 담당자가 체감할 효과가 없다.
- 따라서 **UI 체크박스는 만들지 않는다**. API 파라미터 `/assignments?fair=1` 만 제공하고, 효과는 이 문서의 **스트레스 테스트 표**로 설명한다.
- 운영 데이터로 바꿨을 때 fair 가 결과를 바꾸는 날이 생기면 그때 UI 를 활성화한다 (feedback-roadmap 로드맵 6).

## 6. 재현

```bash
python3 /tmp/fairness-measure.py  # 또는 이 문서 작성 시 사용한 스크립트
# → 실 데이터·15명·12명 세 조건에서 11일씩 비교
```

또는 Python 에서 직접:

```python
from assigner import assign
assign('2026-10-14', fair=True)  # 응답에 fairness_applied 필드 포함
```

## 7. API

- `GET /assignments?date=YYYY-MM-DD` — 기존 동작 유지 (fair=False)
- `GET /assignments?date=YYYY-MM-DD&fair=1` — 형평성 제약 적용. 가용 인원 < 요청 농가 수인 날은 응답에 `fairness_applied: false` + `fairness_note` 를 포함.
- 채팅·MCP 도구는 이번 범위에서 건드리지 않음(기본 동작만 노출).
